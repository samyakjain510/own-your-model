# What went wrong (and what changed)

A running list for the write-up. Each entry: what happened, the evidence, and what we changed.

1. **CFPB stopped publishing complaint text (found 2026-11-22).** The live API dropped narratives in Sept 2026. Evidence: `docs/phase0/dataset.md`. Change: text now comes from CFPB's Narratives Archive ZIPs; the data window ends Aug 14, 2026; we plan to share complaint IDs plus a download script rather than re-hosting text.
2. **Every Claude call carried 281,839 hidden prompt tokens (found 2026-11-22).** The CLI loaded all of the user's connected apps as tools. Evidence: usage JSON from the first test call. Change: `--strict-mcp-config` in `src/oym/claude_cli.py`; the same call dropped to 902 tokens. The cache key now includes a runner version so stale measurements aren't reused.
3. **Claude answered with a retired category name (found 2026-11-22).** Asked for a product with no label list, Haiku once said "Credit card or prepaid card", a name CFPB retired in Aug 2023. Change: prompts will list the allowed labels; scoring is exact match; "outdated label" is the first failure category.
4. **I hid the company name from the model (found 2026-11-22).** I filed it under "known later", but the consumer names the company on the intake form. Evidence: pilot misses where the company (e.g. a debt buyer) settles the product. Change: company moved to trace context; prompt route-v2 shows it. Dev product accuracy 0.790 → 0.827 (paired diff +0.037 [0.000, 0.073], n=300).
5. **I ran the pilot on the test set (found 2026-11-22).** Reading test errors and then tuning the prompt would make the test set useless. Change: renamed it `dev_v1`; froze a fresh `test_v2` (seed 20261123) that excludes every dev item and near-copies of them. Prompt tuning happens on dev only.
6. **The near-duplicate check was quadratic (found 2026-11-22).** It rebuilt its index for every item and stalled for 10+ minutes. Change: `NearDupIndex` adds items incrementally; freezing 800 items now takes under a minute.
7. **I ran model training on the laptop without warning, and it hung (2026-11-22).** Two LoRA trials on the M4 16 GB Mac: the first (batch 4) ran out of GPU memory after 7 minutes of heavy swapping; the second (batch 1) worked at ~10 GB peak. Then the Mac hung and had to be restarted, before the planned 6–10 hour job started. Change: no training or model evaluation on the laptop. Those move to free cloud GPUs (Kaggle/Colab). Local work is limited to light data scripts, with a heads-up before anything long or memory-heavy. Smoke-test numbers kept in `runs/smoke-mlx-qwen3-4b/` as a data point only.
8. **The chat template slipped an empty "thinking" block into every training answer (found 2026-11-22).** Qwen3's template renders the final assistant turn as `<think>\n\n</think>\n\n{json}`. After the smoke run, the model printed junk tokens before its JSON. Evidence: raw outputs in `runs/kaggle/oym-qwen3-4b-smoke/results/*/predictions.jsonl`. Change: the training formatter strips the empty block, so the model outputs only the JSON. That matches the inference prompt and saves output tokens, which the cost model counts.
9. **The speed-test job crashed on its first line (found 2026-11-22).** The push script wrote its settings into the Kaggle script as JSON, which spells true as `true`. Python only accepts `True`, so the job died with a NameError after waiting for a GPU. The training jobs hadn't hit this because their settings had no true/false values. Change: both push scripts now write the settings in Python syntax (`repr`).
10. **My first Claude cost figure copied the CLI's billing habits (found 2026-11-22).** The CLI saves every batch of complaints into a one-hour cache at twice the input price, though each complaint is read once. Haiku also thought before answering on 23 of 30 calls, 138 thinking tokens per complaint against 49 answer tokens. Evidence: `usage` in `runs/dev-haiku55-route-v2-n300/calls.jsonl`; the CLI's own figure was $0.238 per 1,000. Change: `cost.py` now prices Claude as a well-built API setup would pay: complaint text at the plain input price, the shared instructions as cache reads. It keeps the thinking tokens, because the measured accuracy includes them. The result is $0.168 per 1,000 standard and $0.084 with batch. A no-thinking figure ($0.049 with batch) is reported as a what-if, since I haven't measured accuracy without thinking.
11. **The PII scrubber missed whole formats (measured 2026-11-22).** I planted 200 fake values of each kind into real complaints and checked whether any piece survived (`src/oym/pii_eval.py`). Version 1 caught every email, phone and card number. It missed every SSN written with spaces, every account number with letters or dashes, and every address with a direction letter ("12 N Oak St") or in lowercase. It never catches a person's name, because a name has no fixed shape. Change: `regex-v2` covers those formats. On fresh fake values it caught all 200 of each kind except names, and it flagged none of 2,212 dates, amounts and times swapped into the complaints. Two limits: I wrote both the test formats and the fixes, so formats I didn't think of will still leak; and names need a name-finding model, which the kit doesn't have yet. CFPB masks names itself, so this case study isn't exposed, but a company's raw logs would be. I also dropped one test format after the first run: a bare company web address ("smithpay.com"), because that isn't personal data.
12. **The speed test failed on both engines (2026-11-23).** vLLM 0.34 wouldn't start on Kaggle's T4: the T4 is too old for its fast attention code (it needs compute capability 8+, and the T4 is 7.5), and a fallback needed a missing `cutlass` module. Installing vLLM also replaced `torchao` with a version too old for `peft`, which then broke the plain Hugging Face fallback in the same job. Evidence: `runs/kaggle/oym-bench-qwen3-4b-n2000/bench/*_failed.json`. Next: run the Hugging Face test in its own job without installing vLLM, and try an older vLLM release that still supports the T4. Until then the cost model uses the 1.46 complaints/second measured during training.
